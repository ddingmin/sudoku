# 1:1 고스트 대결 — 설계

서버 없이 친구와 같은 스도쿠로 붙는 비동기 대결. 상대의 풀이 로그를 링크에 담아 받아 온 뒤,
내가 푸는 동안 상대가 **그 시점에 어디까지 채웠는지**를 "고스트"로 보드 위에 겹쳐 보여준다.
결과는 답장 링크로 다시 돌려보낸다. 실시간 동기화·계정·DB는 없다.

## 왜 비동기인가

- 실시간 P2P(WebRTC)도 SDP 교환에 시그널링 서버가 필요하다. 수동 복붙은 500자 이상이 두 번 오가야 해 UX가 무너진다.
- 이 앱의 확산 루프는 카톡 단톡방에 링크가 오가는 것이다. 상대가 접속 중일 필요가 없는 비동기가 오히려 맞다.
- 데일리 퍼즐은 `hashSeed("sudoku:날짜:난이도")`로 결정되므로 **문제 자체는 전송할 필요가 없다.** 자유 모드는 시드 32비트만 실으면 된다.

## 이미 있던 것 / 새로 필요한 것

| 재료 | 상태 |
|---|---|
| 같은 퍼즐 보장 (날짜·난이도 → 시드) | 있음 (`lib/sudoku.ts`) |
| 무브 순서 전체를 담는 공유 코드 (v3, 8비트/무브) | 있음 (`lib/encode.ts`) |
| 무브 로그 타임랩스 렌더러 | 있음 (`RecapBoard`) |
| **무브별 시간축** | v3가 버림(하이라이트만 남김) → 대결 코드에서 체크포인트로 보강 |
| 고스트 오버레이·진행 비교·승패 판정 | 신규 |
| 도전장/결과 랜딩 + OG | 신규 (`/duel/[code]`) |

## 대결 코드 (`lib/duel.ts`)

`/duel/<code>` 한 종류의 라우트에 도전장과 답장이 모두 실린다. 접두 `"4"`(공유 코드 v3 `"3"`, 백업 `"1"`과 구분).

```
"4" + 비트열(6비트 = base64url 1문자)
  종류 1                      0 = 도전장 · 1 = 답장
  [답장] 상대 요약             시간 17 · 실수 7 · 힌트 7     ← 원 도전자의 결과 (승패 카드용)
  체크포인트有 1
    [有] 개수 6 · 개수 × 누적 초 13   ← 10무브마다 그 시점 경과 초 (최대 8191초)
  기록 본문 (v3와 동일 레이아웃, 무브가 마지막)
```

- 기록 본문은 `encode.ts`의 `writeRecordBits/readRecordBits`를 그대로 쓴다. v3 `encodeRecord`도 같은 함수를 사용하므로 두 코드가 어긋나지 않는다.
- 무브 개수는 v3처럼 "남은 비트 / 8"로 추정한다. 앞에 붙는 비트가 얼마든 6비트 패딩은 8비트 미만이므로 안전하다.
- **시간 복원**: 앵커 (−1, 0초) · (9, cp₀) · (19, cp₁) · … · (마지막, 총 시간) 사이를 선형 보간한다. 10무브 단위로 정확하고, 그 안은 균등 분포로 본다.
  단, v3 본문에 이미 실려 있는 "가장 오래 고민한 칸"(`longestThink`: 칸·초)이 속한 구간은 그 무브에 고민 시간을 몰아준다 — 추가 비트 없이 고스트가 실제로 멈췄던 자리에서 멈춘다.
  검증 스크립트의 최악 케이스(한 구간에 200초 고민)에서 복원 최대 오차는 체크포인트만으로 ~140초, 고민 앵커를 더하면 ~25초.
- 길이: 무브 300개 기준 체크포인트 30개 × 13비트 ≈ 65자 추가 → 도전장 약 150~170자. 카톡·슬랙·X 미리보기 모두 문제없는 길이.

### 왜 체크포인트인가

| 방식 | 추가 길이 | 체감 |
|---|---|---|
| 총 시간 균등 배분 | 0 | 고민 구간이 사라져 고스트가 기계적으로 움직임 |
| **10무브 체크포인트** | ~65자 | 고민·스퍼트가 보존됨 |
| 무브당 델타 5비트 | ~250자 | 정확하지만 링크가 3배 |

## 플로우

```
A 클리어 ──"대결 신청"──▶ /duel/<도전장>  ──"받기"──▶  B: 같은 퍼즐 + A의 고스트
                                                              │ 클리어 → 승패 확정
A ◀── /duel/<답장> ◀──"결과 답장"─────────────────────────────┘
       (양쪽 카드 + 승자 스탬프 + 다시 "이 기록에 도전하기")
```

- 답장 코드에도 B의 무브 전체가 들어 있으므로 **답장 자체가 새 도전장**이다. 단톡방의 제3자가 답장 링크를 눌러도 B의 고스트와 붙을 수 있다.
- "받기"는 `/#duel=<code>`로 홈에 진입한다. 해시라 서버에 남지 않고, 홈은 정적 페이지로 유지된다. 진입은 `<a href>` 전체 내비게이션으로 한다 — `<Link>` 클라이언트 전환은 홈의 마운트 이펙트가 URL 갱신보다 먼저 실행돼 해시를 못 본다.
- 홈은 마운트 시 해시를 한 번 읽고(`BootIntent`) 주소에서 지운다. 읽은 결과는 ref에 보관해 dev의 StrictMode 이펙트 재실행에도 같은 게임이 깔리게 한다.
- 진행 중인 대결은 일반 게임과 같은 저장 슬롯 체계(`sudoku:games:v1`)에 `duel` 필드를 붙여 저장한다. 앱을 오갔다 와도 고스트가 이어진다. 지난 데일리라도 대결 슬롯은 폐기하지 않는다(3일 만료만 적용).

## 고스트 규칙

- 보여주는 것: 상대가 **어느 칸을 채웠는지**만. 숫자는 절대 보이지 않는다(정답 유출 방지). 오답을 낸 칸은 정정되기 전까지 체리 점으로 표시.
- 내가 이미 채운 칸에는 고스트 마커를 그리지 않는다(잡음 제거).
- 비교 지표: 정답 칸 수. `내 정답 칸 − 고스트 정답 칸` 을 "N칸 앞서요 / 뒤처졌어요"로 표시. 경과 시간이 상대 기록을 넘으면 "상대 기록 지남"으로 바꾼다.
- 승패: 클리어 시간만 비교. 동일하면 동점. 실수·힌트는 카드에 나란히 보여주되 판정에 넣지 않는다(단순함 우선).

## 기록 정책

- 대결 게임도 플레이/클리어 수에 들어간다.
- 데일리 잔디·스트릭은 **오늘 날짜의 데일리 퍼즐인 경우에만** 찍힌다. 어제 도전장을 오늘 받으면 자유 게임으로 집계한다(과거 잔디 소급 방지).
- 난이도별 베스트는 자유·데일리 통합이던 기존 규칙 그대로 적용.

## 공정성 — 정직하게

서버가 없으니 검증이 없다. 시간·무브 로그는 클라이언트가 만든 값이며 조작할 수 있다.
이 기능은 **랭킹이 아니라 친구끼리의 자랑**이라는 전제에서만 성립한다. 코드 디코딩에서 구조적 무결성(범위·길이)만 확인하고,
"물리적으로 불가능한 시간" 같은 휴리스틱 판정은 넣지 않았다(오탐 시 링크가 통째로 죽는 비용이 더 크다).
